# 更新与发布管理

这份文档解决两个问题：

1. 你更新后，已经安装的人怎么知道、怎么升级；
2. 你怎么管理多个版本、回滚、兼容旧数据。

先给结论：**不要做“静默自动更新”**。  
DSH 插件是用户本机的 bundle，安全做法是“检查到新版本 → 用户确认 → 通过插件管理器安装”。真正的“同步”依赖发布渠道，而不是在插件里偷偷替换文件。

---

## 一、三种分发方式，能力不一样

| 方式 | 用户怎么装 | 你更新后能否同步 | 适合 |
| --- | --- | --- | --- |
| 发 ZIP / tgz | 插件管理器本地安装 | 不能，必须重新发新 tgz | 家人、朋友、小范围试用 |
| GitHub Releases + 更新清单 | 本地安装，插件提示新版本 | 能提示；用户手动下载安装 | 公开但不想上 npm |
| npm / 私有 registry | 插件管理器按包名安装 | 插件管理器可更新，最接近“同步” | 长期维护、多人使用 |

**推荐路线：**

- 现在：ZIP + GitHub Releases；
- 用户超过 10 个：加 `update.json` + 插件内“检查更新”提示；
- 用户更多或要长期维护：发布到 npm/私有 registry，让 DSH 插件管理器负责版本。

---

## 二、建议增加的功能

### 1. 更新清单 `update.json`

固定放在一个 HTTPS 地址，例如：

```json
{
  "schema": 1,
  "package": "xiaofeiyu-academy",
  "version": "1.3.0",
  "channel": "stable",
  "publishedAt": "2026-12-01T10:00:00Z",
  "download": "https://github.com/你的账号/xiaofeiyu-academy/releases/download/v1.3.0/xiaofeiyu-academy-1.3.0.tgz",
  "sha256": "……",
  "size": 7900000,
  "minDsh": "1.0.0",
  "notes": ["新增 xxx", "修复 xxx"]
}
```

规则：

- `download` 必须是 HTTPS；
- `sha256` 用于校验安装包；
- `minDsh` 声明最低 DSH 版本；
- `version` 必须和 `package.json` 一致；
- 更新清单最后上传，确保下载地址已经可用。

### 2. 插件内“检查更新”

建议放在 **家长设置 → 关于小肥鱼**：

- 显示当前版本、更新日期、发布说明；
- 按钮「检查更新」；
- 有新版本时显示：版本号、更新内容、下载按钮、「复制安装方法」；
- **不要自动下载后执行**，也不要在用户不知情时替换 bundle；
- 失败时静默降级，不打扰孩子学习。

实现上让 Host 代取清单（避免浏览器跨域），缓存 6 小时；清单 URL 只允许 HTTPS 和固定的 GitHub/registry 域名。

### 3. 版本与迁移

- 建议语义化版本：`1.2.1` 修复、`1.3.0` 功能、`2.0.0` 破坏性变更。
- `STORAGE_KEY` 保持 `xiaofeiyu-academy:v1` 不变；数据迁移写在 `normalizeState`。
- 如果必须改 storage key，先做“导出/导入”功能，不能直接丢用户数据。
- `cordis.patch.yml` 的 bundle id/name 不能随便改，否则用户会装成两个插件。

### 4. 发布脚手架

仓库里已带：

- `scripts/build-release.ps1`：检查语法、`npm pack`、计算 SHA256、生成 `update.json`、打 ZIP、写校验文件。
- `release/update.json`：本次示例清单，必须把 `BaseUrl` 换成你的真实发布地址后重新生成。
- `CHANGELOG.md`：版本变更记录。

## 三、发布一次的标准流程

1. 修改 `package.json` 的 `version`。
2. 更新 `CHANGELOG.md`。
3. 运行：

```powershell
node --check client.js
node --check index.js
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-release.ps1 `
  -BaseUrl "https://github.com/你的账号/xiaofeiyu-academy/releases/download/v1.3.0" `
  -Channel stable `
  -Notes "新增：xxx`n修复：xxx" `
  -MinDsh "1.0.0"
```

4. 在 GitHub 创建 tag `v1.3.0` 和 Release。
5. 上传：
   - `release/xiaofeiyu-academy-1.3.0.tgz`
   - `release/xiaofeiyu-academy-v1.3.0-installer.zip`
   - `release/update.json`
   - `release/SHA256SUMS.txt`
6. **最后**确认 `update.json` 的下载地址可访问，再让插件检查更新。
7. 让用户通过插件管理器安装/更新。

> 不要覆盖旧 tag 的资产；旧版本保留，方便回滚。

## 四、GitHub Actions 已配置

仓库里已带 `.github/workflows/release.yml`：

- push `v*` tag 时自动触发；
- 检查 `package.json` 版本和 tag 是否一致；
- 调用 `scripts/build-release.ps1` 打包、生成 `update.json`、校验值；
- 用 GitHub 自带 token 创建 Release 并上传资产；
- 不需要你手动上传 ZIP，也不需要 PAT。

### 第一次建仓 / 推送

```bash
git init -b main
git add .
git commit -m "chore: release xiaofeiyu academy v1.2.1"

# 在 GitHub 上新建一个空仓库，然后：
git remote add origin https://github.com/MagicSandBag/xiaofeiyu-academy.git
git push -u origin main

git tag v1.2.1
git push origin v1.2.1
```

推送 tag 后，GitHub Actions 会自动生成 Release。  
如果仓库是 **private**，Release 资产默认需要登录才能下载，家长会装不了；要分享给别人就用 public 仓库，或把资产放到可公开访问的对象存储。

### 更新地址

稳定地址：

```text
https://github.com/MagicSandBag/xiaofeiyu-academy/releases/latest/download/update.json
```

对应安装包：

```text
https://github.com/MagicSandBag/xiaofeiyu-academy/releases/download/v1.2.1/xiaofeiyu-academy-1.2.1.tgz
```

**检查更新**：v1.2.1 起，家长设置 → 关于小肥鱼 → 检查更新会读取上面的 latest 地址，并显示版本、更新内容和下载按钮。

## 五、用 npm 做“同步更新”

如果你选择 npm/私有 registry：

1. `package.json` 的 `"private"` 改为 `false`。
2. 确认包名可用；如果使用 scoped 包名，要同步改 `cordis.patch.yml` 的 `name`。
3. 发布：

```bash
npm publish --access public
```

4. 用户第一次按包名 `xiaofeiyu-academy` 安装；后续你发布新版本，用户在 DSH 插件管理器里更新/重装即可。

优点：

- 用户不需要每次找你要新 ZIP；
- 版本、依赖、完整性由 registry 管理；
- 回滚可以发布旧版本或 `npm deprecate` 标记问题版本。

注意：

- 小肥鱼形象来自 `dsh-pet`，仅供非商用；不要公开售卖。
- npm 包名被占用时，需要换名并同步改 bundle 名，不能只改 package 名。
- DSH 插件管理器的具体更新按钮随版本不同；如果它不支持自动更新，仍以 `update.json` 提示 + 本地安装为准。

## 六、回滚与兼容

- 保留最近 3 个版本的 tgz。
- 新版本出问题时，把 `update.json` 的 `version/download/sha256` 指回上一个稳定版。
- 数据结构只做向前兼容；不要在新版本里删除旧字段。
- 每次发布前验证：
  - 旧版 localStorage 能否加载；
  - 多孩子档案是否还在；
  - 教材 PDF 能否解析；
  - 移动端和全屏入口是否正常；
  - 安装包在临时目录能否 `npm install`。

---

## 七、建议的发布节奏

- **补丁版**：修错别字、兼容性、单个 bug，随时发。
- **功能版**：教材/错题/报告等成组更新，先在 `beta` 通道放 1–2 天。
- **大版本**：改数据结构或 bundle 名称时，提前在 README 写明迁移方式。
